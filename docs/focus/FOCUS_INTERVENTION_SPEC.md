# Razuma Focus — спецификация интервенций (16 сценариев)

Статус: **черновик для реализации** (EMO-17). Источник — набор анимационных
прототипов ОРИ из [`focus-assets/`](../../focus-assets/) (16 GIF, слои персонажа,
генератор и оффлайн-просмотрщик `ORI_16_Animations.html`).

> Все эмоциональные правила остаются **экспериментальными**. Это приглашение к
> разговору, а не доказательство потери фокуса и не медицинская оценка. Каждый
> жест проигрывается **один раз на событие** — GIF зациклены только для просмотра.

## Обозначения

| Символ | Значение |
|---|---|
| `z` | изменение относительно **личного уровня**, снятого в подтверждённый период работы (robust z-score: `(x − median) / (1.4826 · MAD)`, пол 0.05) |
| `V` | валентность, диапазон `[−1, 1]` |
| `A` | активация, диапазон `[0, 1]` |
| `I` | интенсивность экспрессии, диапазон `[0, 1]` |
| `z ≥ 2` | рост относительно личного уровня |
| `z ≤ −2` | снижение относительно личного уровня |

Внутри строки все условия соединяются через **И**, кроме явно указанного **ИЛИ**.
Условие должно выполняться **не менее 80 % указанного окна** и сохраняться в
**последнем валидном измерении**. Недоступное значение **не заменяется нулём** —
правило, зависящее от него, отключается (строка 16).

## Общие настройки реализации

- **Исходный период** — минимум **60 секунд** подтверждённой работы (≥16 валидных
  кадров, ≥80 % временного покрытия).
  - **Пилот.** Реальные веб‑камеры часто не находят лицо (движение, свет), поэтому
    80 % покрытия окна недостижимы: у тестовой сессии было 38 валидных кадров за
    121 с (~31 %). Порог подтверждения понижен до **25 % валидных кадров**
    (`emotionPolicy.baselineCoverage`), при этом сохраняются требования «≥16
    валидных кадров» и «интервал ≥60 с». Диагностика показывает именно **число
    валидных кадров и покрытие**, а не секунды, чтобы «121 с из 60» не выглядело
    готовностью при низком покрытии.
- Названия **девяти категорий** (`interest`, `joy`, `surprise`, `fear`, `anger`,
  `sadness`, `shame`, `contempt`, `disgust`) и шкалы **сверить с реальным API Razuma**.
  - **Проверено на реальном ядре** (`models/enet_b0_8_va_mtl.pt`, 8 классов + va_mtl):
    доступны восемь категорий — `anger`, `contempt`, `disgust`, `fear`, `joy`
    (из `happiness`), `neutral`, `sadness`, `surprise`. Каналов `interest` и `shame`
    **нет**. Поэтому строка 1 применяется в **экспериментальном** виде: клаузулы
    `interest` / `shame` опускаются, остальные условия (`joy ≤ 0`, `surprise ≤ 0`,
    `max(негатив) < 2`, `|zV| < 2`, `zA ≤ −2`, `zI ≤ −2`) сохраняются. Недоступное
    значение по-прежнему **не подменяется нулём**.
- **Автоматические предложения 1–4**: только при явном включении пользователем,
  **не чаще одного раза в 5 минут**, **максимум 2 за сессию**. При паузе или уже
  открытой карточке новое предложение **не показывать**.
- Если доступны **только эмоциональные каналы**, строка 1 запускает
  **экспериментальную проверку состояния**, а не устанавливает «зависание».
- **Явный выбор пользователя имеет приоритет** над автоматическими правилами.
  Одновременно показывается **одна** реакция; остальные **не ставятся в очередь**.
- Все движения **плавные, `ease-in-out`, без отскока**. Позиция Нумы **постоянная**.
  В режиме без анимации остаются **только статичные карточки**.
- Для обоих звуков: стартовый цифровой пик **−24 dBFS**, с регулировкой и
  **предварительным прослушиванием**. Звуки **не усиливаются автоматически**.
- Кадры обновляются с частотой **1–2 с** (окно требует ≥8 ответов в 15 с).
- **Порог удержания** для авто-предложений: в спецификации номинально **80 %** окна.
  В пилоте используется **60 %** (`emotionPolicy.patternPersistence`), потому что
  покадровые оценки эмоций шумят и 80 % по 15–30 с почти недостижимы; требование
  «сохраняться в последнем валидном измерении» остаётся. Порог калибруется по
  отладочным значениям `progress` (`?debug=1`).
- **Устойчивость к шуму.** Покадровые z-оценки сглаживаются медианой по
  `emotionPolicy.smoothFrames` (3 кадра), а удержание по окну считается как доля
  валидных кадров, удовлетворяющих правилу, — одного «плохого» кадра недостаточно,
  чтобы отменить устойчивое сочетание. Окно решения привязано к **последнему
  валидному кадру**, а не к последнему кадру вообще (при sparse-детекции лицо
  пропадает в большинстве кадров), но не старше `emotionPolicy.maxStaleMs` (10 с):
  если лицо не видно дольше, система молчит, а не срабатывает по устаревшим данным.
  Требование последнего валидного кадра и запрет подмены недоступного канала нулём
  сохраняются.

## 1. Проверка возможного «зависания» при снижении экспрессии

- **Назначение.** Мягко уточнить, в задаче ли пользователь. Сочетание встречается и
  при сосредоточенной работе, поэтому запускает **только вопрос**, без оценки.
- **Формула / условие.**
  - Эмоции: `zИнтерес ≤ −2`; `zРадость ≤ 0`; `zУдивление ≤ 0`;
    `max(zСтрах, zГнев, zГрусть, zСтыд, zПрезрение, zОтвращение) < 2`.
  - `V`: `abs(zV) < 2`.
  - `A`: `zA ≤ −2`.
  - `I`: `zI ≤ −2`.
  - Окно: **30 с**.
- **Анимация.** Один цикл, **900 мс**. `0–250` — приподнять голову на 4 % высоты
  персонажа; `250–450` — наклонить голову на 6° и поднять лапу до груди;
  `450–650` — удержать позу; `650–900` — вернуться в исходное положение.
  Карточка появляется рядом, **не сдвигая рабочий контент**.
- **Звук.** Один тон «ту»: **440 Гц, 400 мс**, синусоида. Нарастание 80 мс,
  удержание 120 мс, затухание 200 мс. Без эха и повторов. Только при включённом звуке.
- **Сообщение и кнопки.** «Ты сейчас в задаче?» — «Да, продолжаю» /
  «Помоги вернуться» / «Нужна пауза».

## 2. Предложение помощи при росте гнева / отвращения и активации

- **Назначение.** Предложить помощь при выраженном негативном напряжении.
- **Формула / условие.**
  - Эмоции: `max(zГнев, zОтвращение) ≥ 2`; `max(zГнев, zОтвращение) > zСтрах`.
  - `V`: `V < 0`; `zV ≤ −2`.
  - `A`: `zA ≥ 2`.
  - `I`: `zI ≥ 2`.
  - Окно: **15 с**. Другие эмоции не ограничивают срабатывание.
- **Анимация.** Один цикл, **700 мс**. `0–250` — наклонить голову на 5° к карточке;
  `250–450` — удержать позу; `450–700` — вернуться. Выражение лица нейтральное.
- **Звук.** Не воспроизводится.
- **Сообщение и кнопки.** «Нужна помощь с текущим действием?» — «Разбить на шаги» /
  «Продолжить самостоятельно» / «Сделать паузу».

## 3. Предложение поддержки при росте страха и активации

- **Назначение.** Предложить поддержку при выраженном страхе.
- **Формула / условие.**
  - Эмоции: `zСтрах ≥ 2`; `zСтрах ≥ max(zГнев, zОтвращение)`.
  - `V`: `V < 0`; `zV ≤ −2`.
  - `A`: `zA ≥ 2`.
  - `I`: `zI ≥ 2`.
  - Окно: **15 с**. При равном росте страха и гнева/отвращения выбирается **эта** строка.
- **Анимация.** Один цикл, **900 мс**. `0–300` — развести лапы ладонями вверх на
  уровне корпуса, смещение каждой не более 5 % ширины персонажа; `300–500` —
  удержать позу; `500–900` — опустить лапы. Без испуганной мимики.
- **Звук.** Не воспроизводится.
- **Сообщение и кнопки.** «Как тебе удобнее продолжить?» — «Продолжить работу» /
  «Нужна помощь» / «Сделать паузу».

## 4. Напоминание действия при росте грусти и снижении активации

- **Назначение.** Напомнить текущее действие. Не интерпретировать сочетание как
  установленную усталость или потерю внимания.
- **Формула / условие.**
  - Эмоции: `zГрусть ≥ 2`.
  - `V`: `V < 0`; `zV ≤ −2`.
  - `A`: `zA ≤ −2`.
  - `I`: **не участвует** в условии.
  - Окно: **15 с**.
- **Анимация.** Один цикл, **800 мс**. `0–250` — повернуть голову на 8° к карточке;
  `250–450` — указать лапой на карточку; `450–550` — удержать жест;
  `550–800` — вернуться в исходную позу.
- **Звук.** Не воспроизводится.
- **Сообщение и кнопки.** «Напомнить текущее действие?» — «Показать» /
  «Продолжить самостоятельно» / «Сделать паузу».

## 5. Рост радости / интереса без активных сочетаний

- **Условие.** `zРадость ≥ 2` **ИЛИ** `zИнтерес ≥ 2`. `V/A/I` не участвуют.
  Ни одно правило 1–4 не сработало.
- **Смысл.** Не считать подтверждением концентрации или завершения задачи.
- **Анимация.** Не запускается. Нума неподвижна; не празднует в ответ на мимику.
- **Звук.** Не воспроизводится. **Сообщения нет.**

## 6. Рост удивления без активных сочетаний

- **Условие.** `zУдивление ≥ 2`. `V/A/I` не участвуют. Ни одно правило 1–4 не сработало.
- **Анимация.** Не запускается. Нума не копирует удивление пользователя.
- **Звук.** Не воспроизводится. **Сообщения нет.**

## 7. Рост стыда / презрения без активных сочетаний

- **Условие.** `zСтыд ≥ 2` **ИЛИ** `zПрезрение ≥ 2`. `V/A/I` не участвуют.
  Ни одно правило 1–4 не сработало.
- **Смысл.** Не делать вывод об отношении пользователя к задаче.
- **Анимация.** Не запускается. Нума неподвижна.
- **Звук.** Не воспроизводится. **Сообщения нет.**

## 8. Другие сочетания / обычная работа

- **Условие.** Ни одно активное правило 1–4 не сработало, в том числе при коротком
  всплеске или изменении только `V`, только `A` либо только `I`.
- **Анимация.** Полная статичность: без покачивания, дыхания, автоматического
  моргания и слежения за курсором.
- **Звук.** Тишина. **Сообщения нет.** Помощь остаётся доступной по запросу.

## 9. Пользователь выбрал «Помоги вернуться» или «Показать»

- **Условие.** `answer = help_return` **ИЛИ** `answer = show_current_action`.
  Эмоции и `V/A/I` не участвуют.
- **Анимация.** Один цикл, **800 мс**. Повернуть голову на 8° к карточке за 200 мс →
  вытянуть лапу к ней за 200 мс → удержать 150 мс → вернуться в исходную позу за 250 мс.
- **Звук.** Не воспроизводится: второй сигнал после вопроса не нужен.
- **Сообщение и кнопки.** «Текущее действие — [сохранённое действие]». —
  «Продолжить» / «Разбить на шаги» / «Сделать паузу».

## 10. Пользователь выбрал продолжение без помощи

- **Условие.** `answer = continue`. Одинаковое действие для кнопок «Да, продолжаю»,
  «Продолжить», «Продолжить работу» и «Продолжить самостоятельно».
- **Анимация.** Нума неподвижна. Карточка исчезает за **150 мс**.
- **Звук.** Не воспроизводится. **Без дополнительного сообщения.**

## 11. Пользователь запросил помощь

- **Условие.** `answer = help`. Эмоции и `V/A/I` не участвуют.
- **Анимация.** Без дополнительного движения. Содержание текущей карточки заменяется
  выбором помощи.
- **Звук.** Не воспроизводится.
- **Сообщение и кнопки.** «Что поможет продолжить?» — «Показать текущее действие» /
  «Разбить на шаги» / «Сделать паузу».

## 12. Пользователь выбрал разбиение на шаги

- **Условие.** `answer = split_into_steps`. Открыть предложения шагов для текущего
  действия; применять изменения **после** выбора пользователя.
- **Анимация.** Нума неподвижна. Открывается статичная карточка предложенных шагов.
- **Звук.** Не воспроизводится.
- **Сообщение и кнопки.** «Предлагаю такие шаги: [список]». — «Использовать эти шаги» /
  «Изменить» / «Назад».

## 13. Пользователь выбрал паузу

- **Условие.** `answer = pause`. Приостановить сессию и автоматические предложения;
  сохранить текущее действие.
- **Анимация.** Переход, **600 мс**. Опустить лапы и голову на 3 % высоты персонажа.
  Затем неподвижность, **без имитации сна**.
- **Звук.** Не воспроизводится.
- **Сообщение и кнопки.** «Пауза. Можно вернуться в любой момент». — «Вернуться к задаче».

## 14. Подтверждённое завершение действия

- **Условие.** `userMarkedDone = true` **ИЛИ** `verifiedTaskCompletion = true`.
  Реакция — **один раз на событие**. Эмоции и `V/A/I` не участвуют.
- **Анимация.** Один цикл, **650 мс**. `0–200` — наклонить голову вниз на 7°;
  `200–450` — вернуть голову; `450–650` — небольшая улыбка. Без прыжков и конфетти.
- **Звук.** Две ноты «ту-ду»: **523 Гц — 160 мс**; пауза — 60 мс; **659 Гц — 220 мс**.
  Синусоидальные тоны; атака каждой ноты 30 мс, затухание 80 мс входят в её длительность.
  Только при включённом звуке завершения.
- **Сообщение и кнопки.** «Готово. Следующее действие — [действие]». Если завершена
  вся задача: «Задача завершена».

## 15. Нет ответа на автоматическое предложение

- **Условие.** Через **20 с** после появления карточки `answer = null` → закрыть
  карточку; записать ответ как **неизвестный**. Не считать молчание подтверждением
  отвлечения.
- **Анимация.** Карточка исчезает за **200 мс**. Нума не повторяет жест.
- **Звук.** Не повторяется и не усиливается. **Сообщения нет.**

## 16. Недостаточно данных для анализа

- **Условие.** Нет обязательного канала, подтверждённого исходного уровня или
  пригодных данных → **отключить зависимое правило**. Недоступное значение **не
  заменять нулём**.
- **Анимация.** Нума неподвижна. При недоступности анализа — статичный индикатор
  **без мигания**.
- **Звук.** Не воспроизводится.
- **Сообщение.** «Анализ временно недоступен». Помощь по запросу сохраняется.
