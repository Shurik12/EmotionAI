# Razuma — Vite + React + TypeScript

Чистое SPA: 68 экранов исходного UX, роли врача и пациента, графики и отдельный компонент записи аудио/видео. Без Next.js, SSR, серверных компонентов и серверных API-маршрутов.

## Быстрый запуск

Нужны Node.js 20+ и npm. Откройте терминал в этом каталоге (`compass/frontend`):

```sh
npm ci
npm run dev
```

Откройте адрес, который покажет Vite (обычно http://localhost:5173).

## Статическая сборка

```sh
make build_compass      # из корня репозитория: npm install + vite build
npm run build           # или отсюда напрямую
```

Сборка пишется не в локальный `dist/`, а в `frontend/dist/compass/` лендинга (`base: './'`) и
публикуется вместе с ним по адресу https://razuma.tech/compass/. Node.js на хостинге не нужен:
сборка статическая, а относительные пути ресурсов и hash-навигация работают в подкаталоге без
SPA-rewrite. Локальная проверка в прод-подобном виде:

```sh
cd ../../frontend/dist && python3 -m http.server 8080   # http://localhost:8080/compass/
```

Открывайте через HTTP(S), а не двойным щелчком по HTML через file://. Для камеры и микрофона нужны
HTTPS или localhost и разрешение браузера.

Примеры адресов: `/#/screens/P03`, `/#/screens/D01`, `/#/capture`. Список всех экранов — `docs/screens.md` и встроенный каталог.

## Что работает

- 32 экрана пациента, 32 экрана врача, 4 общих экрана.
- Переключение демонстрационных ролей и пациентов, формы и переходы, кнопка «Назад» браузера.
- Графики как React SVG, иконки, адаптивный интерфейс исходного UX.
- На `#/capture`: настоящая запись камеры/микрофона, предпросмотр, остановка через 60 секунд, скачивание и удаление записи. Медиа остаётся в памяти вкладки, не загружается на сервер и не анализируется.

## Границы демонстрации

Это UX-прототип, а не готовая клиническая система. Данные учебные, роли не обеспечивают разграничение доступа. Состояние хранится в памяти и сбрасывается после перезагрузки или выхода из основного прототипа на страницу записи. Запись пока не прикрепляется к дневнику автоматически. На исходных экранах P07/P08 таймер записи — имитация; для настоящей записи используйте ссылку в верхней панели.

Результаты анализа, тревожные уведомления, вход по коду, отправка врачу и экспорт внутри UX — демонстрационные сценарии. Реальные анализ Razuma/ML, доставка уведомлений и медицинская валидация не подключены. Не используйте прототип для принятия медицинских решений или обработки настоящих данных пациентов.

## Подключение API

Типизированный контракт находится в `src/lib/api.ts`: сохранение записи, загрузка медиа, получение статуса анализа. Экраны пока не вызывают этот адаптер. Скопируйте `.env.example` в `.env.local`, задайте публичный `VITE_API_BASE_URL` и пересоберите приложение. При пустом адресе адаптер явно сообщает, что сервер не подключён.

Сервер разрабатывается отдельно: авторизация и проверка ролей, хранение согласий и данных, аудит, очереди анализа, проверка результатов врачом и подтверждаемая доставка уведомлений. Для другого домена настройте CORS и политику авторизации. Адаптер по умолчанию передаёт cookie только своему origin. **Не помещайте секреты и ключи Razuma в переменные VITE_: они видны посетителю в сборке.**

## Структура

- `src/App.tsx` — маршрутизация SPA.
- `src/components/` — React-компоненты интерфейса, графиков и записи.
- `src/prototype/engine.js` — сохранённая логика 68 экранов с декларацией TypeScript; это адаптер исходного UX, а не полная перепись всех шаблонов в TSX.
- `src/data/screens.json` — реестр экранов.
- `src/styles.css` — стили исходного UX.
- `reference/original-ux.html` — исходник для сверки, не используется как iframe.
- `../../frontend/dist/compass/` — статическая сборка (создаётся вне этого каталога).

## Проверки

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

Браузерный тест запускает preview самостоятельно, проверяет роли, каталог 68 экранов, формы, навигацию, мобильную ширину и запись с тестовым устройством. Для установленного Chromium можно указать переменную `CHROMIUM_PATH`.
