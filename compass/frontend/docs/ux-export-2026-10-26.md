# Compass: экспорт UX для CTO
Дата: 26.10.2026
База: f6006150dd2e0d973e793695400443f649b425bf
Инструкция: https://github.com/Shurik12/EmotionAI/blob/f6006150dd2e0d973e793695400443f649b425bf/compass/frontend/docs/export-requirements.md

Это точечный экспорт согласованного дизайна «Тёплый коралл / унисекс» в существующий Compass.
Исходники не переписаны целиком. В GitHub ничего не отправлено, сайт не опубликован.

## Что передать разработчику

1. Razuma_Compass_UX.patch — патч к указанному коммиту. Меняет три рабочих файла и `package.json` (скрипты тестов), добавляет этот документ.
2. Razuma_Compass_CTO.txt — инструкция применения, результаты и ограничения.
3. Razuma_Compass_Export.pdf — сравнение исходного и реализованного интерфейса; реальные скриншоты браузера.
4. Razuma_Compass_Static.zip — отдельная статическая сборка для просмотра. Это не архив исходного SPA и не способ переноса правок в репозиторий.

## Применение патча

В корне EmotionAI, после сохранения собственных незакоммиченных изменений:

git status --short
git apply --check /path/to/Razuma_Compass_UX.patch
git apply /path/to/Razuma_Compass_UX.patch

Замените /path/to/ на фактическую папку скачивания.
Патч подготовлен к зафиксированному коммиту по ссылке. Если текущий код уже изменён и проверка не проходит, не применяйте его принудительно. Перенесите изменения по смыслу, сохранив доработки CTO; весь проект и конфигурацию заменять не нужно.

В compass/frontend, на Node.js 20 и npm 10:

npm ci
npm run typecheck
npm test
npm run build
npm run test:ux:browser
npm run test:browser

Для браузерных тестов нужен Chromium, установленный для Playwright, либо CHROMIUM_PATH.
При необходимости: npx playwright install chromium.
Дополнительный тест принимает UX_SCREENSHOTS_DIR — каталог для снимков проверяемых экранов.

Из корня репозитория:

make build_frontend

Эта команда собирает сначала лендинг, затем Compass. Самостоятельная последующая сборка лендинга удалит подкаталог Compass — порядок сохранён.

## Где лежит результат сборки

frontend/dist/compass/index.html
frontend/dist/compass/assets/

base: './'; hash-роуты; один JS-чанк; sourcemap: false; esbuild; target: es2020.
В статическом архиве — папка compass/ с теми же тремя файлами сборки.

Для просмотра архива распакуйте его в отдельный каталог и запустите из этого каталога:
python3 -m http.server 8080
Откройте http://localhost:8080/compass/#/screens/P03
Используйте HTTP(S), не file://. Для камеры и микрофона — localhost или HTTPS.
Локальный статический сервер не содержит API. Для работы анализа нужен существующий бэкенд; в штатной конфигурации страница P08 обращается к /api.

## Сопоставление UX-01…UX-08

UX-01 — выполнено: две заметные кнопки записи и отдельное действие анализа.
UX-02 — выполнено: новая компоновка, ясный вопрос, мгновенное значение слайдера, сохранение выбора.
UX-03 — частично: выбор причины и его сохранение работают. Отдельное поле свободного уточнения не добавлено: его нет в текущем API-контракте. Показан существующий переход к сообщению врачу.
UX-04 — выполнено для прототипа: пояснение при пропуске и явно демонстрационные статусы. Реальную доставку этот экспорт не добавляет.
UX-05 — выполнено: переписка сохранена, ожидания ответа ясны, отметка просмотра врачом удалена.
UX-06 — выполнено на обновлённых пациентских экранах: заметная кнопка открывает существующий P22. Медицинские тексты и маршрутизация не изменены.
UX-07 — выполнено: изменения и задачи перед приёмом, данные шкал и Razuma. Активное событие безопасности остаётся выше сводки.
UX-08 — выполнено: унисекс-оформление, графики перенесены из основного акцента главной в существующий дневник, адаптивная компоновка.

## Что намеренно осталось существующим

- Обе кнопки записи открывают /capture. Для аудио нужно выбрать «Аудио» в поле «Формат»; видео — значение по умолчанию. Компонент Recorder.tsx не изменён.
- Запись нужно скачать, затем вручную загрузить в P08 для анализа. Автоматическая передача Blob, прикрепление к дневнику и доставка врачу — отдельная интеграция.
- Свободный комментарий к причине пропуска требует отдельного поля в контракте и решения о хранении.
- Роли, дневник, сообщения и клинические сценарии остаются демонстрационными. Патч не добавляет авторизацию, серверное хранение и клиническую валидацию.
- Реальный запрос к медицинскому API и анализ настоящих записей не выполнялись. Запись проверена с тестовым устройством браузера.
- Точная копия сгенерированных иллюстраций не используется вместо интерфейса: экспорт состоит из рабочих DOM-элементов и лёгкой SVG-графики.
